# ha-control

Скилл управления Home Assistant через локальный Rust CLI `{{HA_BIN}}`.
Общение с Home Assistant идёт ТОЛЬКО через этот CLI: никакие прямые
HTTP-запросы, токены, REST/WebSocket API и MCP-клиенты не используются.
Не обращайся к ha-mcp (HTTP/MCP endpoint) напрямую — только через `ha`.

Путь выше — абсолютный путь к установленному бинарнику `ha`,
подставленный инсталлятором на момент установки. Если бинарник
переехал — переустановите скилл.

## Модель данных

Дом описывается семантически: **область (area)** → **домен (domain)** →
**имя (name)**. Пример: область `kitchen`, домен `switch`, имя
`Аэрогриль`.

Сопоставление селекторов **точное** (без учёта регистра, без нечёткого
выбора «похожего»). Следствия:

- Точные имена областей и устройств бери ТОЛЬКО из `context --compact`;
  никогда не угадывай и не конструируй их.
- При подключении CLI к ha-mcp алиасы областей (например, русские
  `кухня`, `спальня`) пока НЕ поддерживаются: работает только точное
  имя области, как его выдаёт `context --compact`.
- Алиасы сущностей работают как значения `name` (если сущность имеет
  алиасы в каталоге), но не как области.

## Команды

### Шаг 1 — узнай окружение (обязательно перед первым действием)

Компактный контекст дома: области, домены и имена всех открытых
сущностей:

```sh
{{HA_BIN}} context --compact
```

Вызывай это ПЕРВЫМ, если не знаешь точных имён областей/сущностей.
Вывод — одна строка JSON. Не вызывай чаще, чем необходимо (живой
запрос к серверу).

### Шаг 2 — действие

Выполнение интента. Аргумент payload — один аргумент JSON-объектом:

```sh
{{HA_BIN}} intent HassTurnOn '{"area": "kitchen"}'
{{HA_BIN}} intent HassTurnOff '{"area": "bedroom", "domain": "light"}'
{{HA_BIN}} intent HassLightSet '{"area": "kitchen", "name": "Лампа", "color_temp_kelvin": 3000}'
{{HA_BIN}} intent HassGetState '{"area": "bathroom", "domain": "binary_sensor"}'
```

Доступные интенты: `HassTurnOn`, `HassTurnOff`, `HassGetState`,
`HassLightSet`, `HassSetPosition`.

Селекторы — только семантические: `area`, `domain`, `name`.
Комбинируй их для точечного таргетинга. Для света почти всегда
указывай `"domain": "light"` вместе с `area`: массовое действие по
области без домена заденет все разрешённые устройства области, а не
только свет.

Для `HassLightSet` допустимы параметры: `brightness` (0–100, проценты),
`color_temp_kelvin` (1000–12000), `transition` (секунды), `rgb_color`,
`effect`. `color_temp_kelvin` и `rgb_color` нельзя комбинировать.
Для `HassSetPosition` обязателен `position` (0–100).

### Диагностика (опционально)

Список MCP-инструментов сервера (только просмотр, не для вызова):

```sh
{{HA_BIN}} tools --refresh
```

## Правила безопасности

- **Никаких entity_id.** Ключи вроде `entity_id` и значения вида
  `light.kitchen` CLI отклоняет намеренно — это защита от
  необдуманного таргетинга. Не пытайся обойти.
- Действия с физическим эффектом (включение/выключение) выполняй
  только по явной просьбе пользователя или в рамках согласованной
  задачи.
- Payload передавай ровно одним аргументом, shell-экранируй
  корректно; апостроф внутри одинарных кавычек — `'it'\''s'`.
- Один вызов = одна запрошенная операция (она может охватывать несколько
  устройств). **Не повторяй вызов записи
  автоматически**: ошибка (таймаут, потеря связи, сбой ответа) не
  доказывает, что действие не выполнено, — повтор может сработать
  дважды. Сообщи пользователю о неопределённом исходе.
- При частичном сбое многоцелевого действия выполненные цели не
  откатываются: в ошибке указано, для скольких целей из скольких
  действие применилось. Не «дозаказывай» остаток автоматически —
  покажи ситуацию пользователю.
- Не считай неопределённый исход ошибкой «действие не сделано».

## Вывод и ошибки

- Успех: одна строка JSON в stdout с `"ok": true`, поле `speech`
  содержит человекочитаемый результат. При работе через ha-mcp текст
  `speech` формируется заново и НЕ обязан совпадать с прошлым
  Assist-ответом побайтово — не полагайся на его точную формулировку.
- `context --raw` при ha-mcp-подключении выводит агрегированный
  ответ поиска сервера (новый формат), а не прежний текстовый
  `Live Context`; парсить его как старый Assist-текст нельзя.
- Ошибка: JSON `{"ok": false, "error": {"type", "message"}}` в
  stderr и ненулевой exit-код (2 — плохие аргументы, 4 — авторизация,
  5 — связь, 6 — ошибка HA API, 7 — интент не удался, 8 — инструмент
  не найден).
- Ноль совпадений или неоднозначное имя — ошибка до вызова сервиса;
  не пытайся выбрать «самое похожее» устройство сам.
- Никогда не выдумывай имена областей и устройств: бери их из
  `context --compact`.

## Откат

Если сервер ha-mcp недоступен или ведёт себя некорректно, откат —
на стороне конфигурации владельца: убрать `HA_MCP_URL`/`mcp_url`
(вернуться на прежний Assist endpoint) или вернуть старый бинарник.
Скиллу для этого ничего делать не нужно; не переключай протоколы сам.
